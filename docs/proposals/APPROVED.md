# Owner decisions after the Prompt 7 audit (2026-11-26)

The audit (commit `2154461`) changed no behavior. It proposed three changes as diffs, which the owner reviewed. The owner approved the following on 2026-11-26. The validation (P7.3) requires every item below to be listed here and proven by passing tests.

| Change | Decision | Where |
|---|---|---|
| A-post-charset.patch | Applied as proposed. The single POST encodes in the form's `accept-charset`, else the page encoding, else UTF-8; characters the charset cannot represent become `&#NNNN;`. | `fetch.py`, `classify.py`, `finder.py`, `send.py`; `tests/test_charset.py` |
| B-robots-status-rule.patch | Applied, **with one owner change**: 429 on robots.txt means disallow, like network errors and 5xx. Every other 4xx (404/410 missing, 401/403, ...) means allowed. Redirects are followed (also to another host); more than 3 hops counts as missing; an oversized file is parsed up to 2 MB. | `fetch.py`; `tests/test_fetch.py` |
| C-sendlog-ledger-check.patch | Applied as proposed. Preflight refuses when sites claimed in the send log are missing from the ledger (e.g. after restoring an older backup). | `preflight.py`; `tests/test_preflight.py`; `scripts/validate.py` P2.4 order |
| reopen wiring | Requested by the owner. When a send run finishes a batch (not halted), the batch's dry-run outcomes no_form, captcha, login_required, robots_blocked and unclear_fields are recorded in `sites` with no POST and no request. Each is one INSERT with its final status; existing rows are untouched; a ready site is never recorded. `reopen` stays limited to those five statuses. | `ledger.record_no_post_outcomes`, `send.run_send`; tests in `test_send.py`, `test_ledger.py` |
| per-site error guard | Requested by the owner. Everything after a successful claim runs inside a per-site `try/except Exception`. Any unexpected error, including after the POST and inside verify, logs an event, leaves the row as it is (pending unless finish already ran), counts as a breaker failure, and the run continues. No retry, no second POST. | `send._Run._send_one`; tests in `test_send.py` |
| suppression with platform keys | Requested check. The lookup uses the site key (not the bare platform domain), so suppressing one facebook page does not block another. For keys with a path the host is checked too, so suppressing `user.wixsite.com` blocks all its sites. A bare platform (`facebook.com`) cannot be suppressed. | `ledger.is_suppressed`; tests in `test_ledger.py`, `test_send.py` |
| pinned dependencies | Requested by the owner. Exact pins for direct dependencies in `pyproject.toml`; every package pinned in `requirements.lock`; tests fail if the pins disagree or the installed tldextract differs. | `pyproject.toml`, `requirements.lock`; `tests/test_dependencies.py` |
| outage handling | Requested by the owner on 2026-11-27 after the real dry-run, where internet outages were recorded as `robots_blocked` and did not stop the run. A network failure while fetching robots.txt (DNS, connection, timeout) still means the page is not requested, but is now reported as `fetch_error`, so the circuit breaker stops the run. The halt message shows the last error. Real robots refusals (5xx, 429, rules) stay `robots_blocked`. | `fetch.py`, `dryrun.py`, `send.py`; tests in `test_fetch.py`, `test_dryrun.py` |
